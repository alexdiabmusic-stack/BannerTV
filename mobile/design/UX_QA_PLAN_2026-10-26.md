## Weighted scorecard

Score only after actual device/emulator evidence exists. Preserve the pack's target of at least 4.2/5, with no critical failures. Formula: `0.25 × watching + 0.25 × craft + 0.20 × input/accessibility + 0.15 × sports + 0.15 × reliability`. Do not omit untested areas and normalize the remainder into a passing total.

| Area | Weight | Required evidence | Current result |
| --- | --- | --- | --- |
| Find and start watching | 25% | Correct followed game found, truthful availability, successful activation, restart/alternate recovery and correct return. Record task steps/time and wrong turns. | Not scored; UX01–04/14 require work or verification. |
| Visual craft | 25% | Current before/after screens with realistic data; hierarchy, alignment, type, icon/mark sizing, spacing and all component states. | Not scored; archived evidence only. |
| Remote/touch/accessibility | 20% | D-pad and Back traversal on TV; phone target bounds, TalkBack semantics/order, large text, contrast, reduced motion and keyboard. | Not scored; source concerns UX05–07/11. |
| Sports relevance | 15% | NHL/NBA/MLB/NFL/soccer/F1 states and multi-sport priorities; actual provider provenance. | Not scored; existing models preserved but redesigned states not rendered. |
| Performance and reliability | 15% | Responsive lists; retained decoder during panels/resizing; honest loading/cache/outage states; no playback regression. | Not scored; no new runtime test or soak. |

## Content and state matrix

All rows are **pending current-slice runtime verification**. Use isolated test fixtures or an explicitly designated QA profile; never overwrite the user's existing playlists/favourites/drafts. Fixture data must be labelled in test artifacts and must not leak into production live results.

| Dimension | Required cases |
| --- | --- |
| Personalization | 0, 1 and 10+ favourites; no favourite live game; several favourites live; follow/unfollow with saved state retained. |
| Event volume | No games with fresh data; exactly one live game; 15+ live games; no results caused only by a filter; mixed live/upcoming/final. |
| Sport | NHL periods/intermission/OT/SO; NBA quarter/overtime; MLB inning/top/bottom; NFL quarter/clock/possession; soccer half/stoppage/penalties; F1 session/laps; retain PGA and other supported routes. |
| Event transitions | Scheduled → pregame → live → interval → final; delayed/postponed/suspended; replay and unknown. Never turn a provider omission into an invented phase or score. |
| Data | Cold loading; warm refresh; cache with original timestamp; offline; partial resource failure; total score failure; late correction; EPG refresh in progress; stale source reference at activation. |
| Media | No playlist; invalid URL/credentials; no matched stream; provider refusal; silence/buffering; available alternate; no alternate; stream restart; replay ended; captions/audio unavailable; return from PiP/Cast where testable. |
| Text/art | Long club names and translations; missing logos/photos; extreme score widths; absent stats; no news; white/bright/dark team marks; broken image URL. |
| Privacy/spoilers | Hidden final/live scores, article headlines/art and companion context; error messages contain no credential-bearing URL. Preserve saved settings and backup behavior. |

## Input, layout and accessibility matrix

- Phone: compact viewport, landscape, expanded/multi-window, 100%/150%/200% text where supported; keyboard open during playlist setup; long validation errors; screen-reader reading order and selected state; all gesture actions also have explicit controls.
- Adaptive layouts: actual separator/hinge geometry, RTL, content insets and modal-window coordinates; verify the current known window-ownership limitation before claiming foldable support. Keep video at one retained identity across pane changes.
- TV: every D-pad direction from every row/toolbar/panel; row entry/exit, first/last items, empty rows, closing dialogs, returning from player, keyboard Done/Back, long labels and enlarged text. Keep focused bounds and text inside safe margins; no clipping from scale.
- Focus and selection: exactly one visible focus owner; selected state remains visible after focus leaves; restoration targets exist after list changes; no invisible or unreachable actions.
- Contrast: measure rendered text/container and focus-ring combinations in light/dark, pressed, selected and disabled states. Candidate palette calculations are only preliminary evidence. Do not make a disabled critical explanation illegible.
- Motion: reduced/system-disabled animations, no perpetual decorative pulse, no focus bounce that changes navigation geometry; no score update that steals scroll/focus.
- Mac and Apple hardware flows are not this checkout's implementation target. Record them as out of scope for this Android slice, not as passed. Physical Cast/Auto/TV/decoder tests remain pending until compatible hardware exists.

## Regression boundaries

Keep existing playlist storage, EPG matching/revalidation, provider parsing, offline caches, fantasy identifiers/rosters, notifications, cloud-file backup, billing configuration and player/source ownership intact. Do not rewrite stream algorithms as part of a card/theme refactor. Existing engine parity work has a separate audit and acceptance path.

Run relevant navigation/state/presentation regressions when behavior changes. Run the project's applicable unit/lint/package checks after the slice, including shared TV checks when shared code changes. A color-only change needs contrast/render verification rather than tests mirroring color constants. Use the existing controlled build setup; do not run Gradle and the emulator together on the constrained host.

No production purchase or cross-device hardware success can be inferred from development builds. The missing Play configuration and physical hardware remain separate verification limits.

## Evidence required before a polished handoff

For each accepted screen/state, record build SHA, device/OS, viewport/density, text scale, appearance, data source/fixture, capture date and input path. Attach actual before/after renders, not concept art. Preserve a compact problem → change → evidence record tied to UX issue IDs.

List passed, failed, deferred and out-of-scope checks separately. A critical path failure blocks a passing score even if the weighted average is high. Record justified deviations from the chosen direction. Restore any changed test-device settings and the selected QA/user profile, then stop streams and emulator processes.

Until emulator/device QA is resumed, useful work can include implementation, source review, contrast calculations and build/state checks after direction selection. **The visual-quality gate remains open, and the slice must not be described as visually certified or fully at parity.**
